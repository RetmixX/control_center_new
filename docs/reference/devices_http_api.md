# API устройств: лампа, терминал, ИК-барьер

Nov 3, 2026 · @Retmix

## Обзор

Все три устройства — Arduino с Ethernet-шилдом и HTTP-сервером на порту 80, который отвечает в JSON. Устройства сами ничего не отправляют: сервер управляет ими запросами и опрашивает их состояние (рекомендуемый интервал опроса 100–500 мс).

| Устройство | Адрес по умолчанию | Что умеет | Прошивка |
| --- | --- | --- | --- |
| Умная лампа | `http://192.168.2.21/` | 4 светодиода | `SMART_LAMP.ino` |
| Удалённый терминал | `http://192.168.2.22/` | 4 светодиода, 3 кнопки, kill switch, дисплей 20×4 | `smart_term.ino` (Arduino Mega) |
| ИК-барьер | `http://192.168.42.21/` | 3 ИК-датчика расстояния | `IR_BARRIER.ino` (Arduino Mega) |

Адрес каждого устройства меняется по Serial без перепрошивки (раздел «Настройка по Serial»). Барьер по умолчанию стоит в другой подсети (`192.168.42.x`), чем лампа и терминал: если все устройства в одной сети, смените его адрес, например на `192.168.2.23`.

Светодиоды терминала управляются так же, как у лампы, и доступны по тому же пути `/api/lamp`: код, написанный для лампы, работает и с терминалом.

## Общие правила

У всех трёх устройств одни и те же правила обмена; различаются только размер тела запроса и строгость разбора JSON.

- **Формат:** JSON без пробелов, `Content-Type: application/json`. Терминал и барьер добавляют `charset=utf-8`.
- **Методы:** чтение — `GET`. Изменение — `PUT`, `PATCH` или `POST`, они равнозначны. Другие методы (например, `DELETE`) дают `405`.
- **Пути:** query-параметры (`?x=1`) и завершающий `/` игнорируются.
- **Частичные изменения:** можно передать только часть полей, остальные не меняются. Если хотя бы одно значение некорректно, ответ `400`, и не меняется ничего.
- **Ответ на изменение:** итоговое состояние целиком (все светодиоды, все строки дисплея, все пороги), чтобы не делать лишний `GET`.
- **Ошибки:** `{"status":"error","error":"описание"}` с кодом 4xx. Все тексты — в разделе «Ошибки».
- **CORS:** в каждом ответе `Access-Control-Allow-Origin: *`, на `OPTIONS` — `204` с методами `GET, POST, PUT, PATCH, OPTIONS` и заголовком `Content-Type`. К устройствам можно обращаться прямо из браузерного приложения.
- **Авторизации нет:** управлять устройствами может любой в сети.
- **Один клиент за раз:** запросы обрабатываются по очереди, медленный клиент может задержать остальных до 1,5 с. Кнопки терминала и датчики барьера при этом продолжают опрашиваться.
- **Соединение** закрывается после каждого ответа (`Connection: close`). Тело запроса требует заголовка `Content-Length`, chunked не поддерживается.

| Устройство | Макс. тело запроса, байт | Разбор JSON |
| --- | --- | --- |
| Лампа | 95 | Ищет нужные ключи по имени; вложенные объекты и экранирование не поддерживаются |
| Терминал | 600 | Только плоский объект; `\"`, `\\`, `\/`, `\uXXXX` работают; иначе `invalid JSON` |
| Барьер | 127 | Только плоский объект; иначе `invalid JSON` |

У всех устройств есть `GET /health` → `{"status":"ok"}` для проверки, что устройство живо.

## Умная лампа

Лампа управляет четырьмя светодиодами: `red`, `blue`, `green`, `yellow`. В путях вместо `{color}` можно указать `all` — действие применится ко всем четырём. Базовый адрес: `http://192.168.2.21`.

| Метод | Путь | Тело запроса | Ответ |
| --- | --- | --- | --- |
| GET | `/api/lamp` | — | Состояние всех светодиодов |
| PUT, PATCH, POST | `/api/lamp` | `{"red":true,"blue":false}` — любая часть цветов | Состояние всех |
| GET | `/api/lamp/{color}` | — | `{"color":"red","on":true}` (для `all` — состояние всех) |
| PUT, PATCH, POST | `/api/lamp/{color}` | `{"on":true}` | Состояние всех |
| POST, PUT, PATCH | `/api/lamp/{color}/on` | — | Состояние всех |
| POST, PUT, PATCH | `/api/lamp/{color}/off` | — | Состояние всех |
| POST, PUT, PATCH | `/api/lamp/{color}/toggle` | — | Состояние всех; для `all` каждый переключается отдельно |

Значения светодиодов: `true`/`false`, допускаются также `1`/`0`.

Состояние всех светодиодов:

```json
{"status":"ok","leds":{"red":false,"blue":false,"green":false,"yellow":false}}
```

Примеры:

```bash
# включить красный и голубой, остальные не трогать
curl -X PATCH http://192.168.2.21/api/lamp \
  -H "Content-Type: application/json" \
  -d '{"red":true,"blue":true}'

# переключить жёлтый, выключить всё
curl -X POST http://192.168.2.21/api/lamp/yellow/toggle
curl -X POST http://192.168.2.21/api/lamp/all/off
```

## Удалённый терминал

Терминал даёт светодиоды как у лампы, три кнопки с счётчиками нажатий, kill switch и дисплей 20×4 с русским текстом. Базовый адрес: `http://192.168.2.22`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/terminal` | Всё сразу: светодиоды, кнопки, дисплей. Удобно для опроса |
| GET, PUT, PATCH, POST | `/api/leds`, `/api/leds/{color}`, `/api/leds/{color}/on`, `/off`, `/toggle` | Светодиоды — точно как у лампы; `/api/lamp` тоже работает |
| GET | `/api/buttons` | Кнопки: нажата ли сейчас и счётчики |
| POST, PUT, PATCH | `/api/buttons/reset` | Обнулить счётчики нажатий |
| GET | `/api/display` | Текст всех четырёх строк |
| PUT, PATCH, POST | `/api/display` | `{"line0":"...","line3":"..."}` — любая часть строк |
| GET | `/api/display/{0-3}` | `{"line":1,"text":"..."}` |
| PUT, PATCH, POST | `/api/display/{0-3}` | `{"text":"..."}`; `""` очищает строку |
| POST, PUT, PATCH | `/api/display/clear` | Очистить весь дисплей |

### Кнопки

У каждой кнопки есть `pressed` (нажата прямо сейчас) и `count` (сколько раз нажали с включения или сброса). Чтобы не пропустить короткое нажатие между опросами, следите за изменением `count`. Антидребезг 30 мс; счётчики обнуляются при перезагрузке.

| Кнопка | Роль | Вход |
| --- | --- | --- |
| `green` | Старт | D24 |
| `yellow` | Пауза | D22 |
| `red` | Отмена | D23 |
| `kill_switch` | Большая красная кнопка; `true` — сработал (высокий уровень на входе) | D25 |

Ответ `GET /api/terminal` (отформатирован для чтения):

```json
{
  "status": "ok",
  "leds": {"red": false, "blue": false, "green": true, "yellow": false},
  "buttons": {
    "green":  {"pressed": false, "count": 3},
    "yellow": {"pressed": true,  "count": 1},
    "red":    {"pressed": false, "count": 0}
  },
  "kill_switch": false,
  "lines": ["Этап 2", "Нажмите СТАРТ", "", ""]
}
```

### Дисплей и русские буквы

Четыре строки по 20 символов, номера `0`–`3`. Допустимы латиница, цифры, знаки препинания (кроме `\` и `~`), русские А–Я, а–я, Ё, ё и знак `°`. Кириллицу можно передавать как UTF-8 или как `\uXXXX` (так её шлёт Python `requests` с `json=`).

Встроенной кириллицы у дисплея нет, поэтому:

- Буквы, похожие на латинские (`А В Е К М Н О Р С Т Х`, `а е о р с у х`), выводятся латиницей и ничем не ограничены.
- Остальные рисуются своими символами, а их на всём экране **одновременно не больше 8 разных**. Заглавная и строчная считаются разными, повторы одной буквы не считаются.
- Если после изменения их стало бы больше 8, ответ `400`, и дисплей не меняется. Проверяется весь будущий экран, а не только изменяемая строка.

Пример: «Привет, мир!» занимает 5 своих символов (П, и, в, т, м), «Темп 25°C» добавляет ещё один (п). Уложиться проще, если писать заглавными (`СТАРТ`, `ВРЕМЯ`) и оставлять короткие служебные слова латиницей (`OK`, `IP`).

```bash
curl -X PATCH http://192.168.2.22/api/display \
  -H "Content-Type: application/json" \
  -d '{"line0":"Этап 2","line1":"Нажмите СТАРТ"}'
```

После включения на дисплее стартовый экран (`Ready` и IP терминала), его тоже видно через `GET /api/display`.

## ИК-барьер

Барьер считается перекрытым, когда хотя бы один из трёх датчиков видит предмет ближе своего порога (по умолчанию 50 см). Датчики: `top` (вход A3), `middle` (A1), `bottom` (A0). Базовый адрес: `http://192.168.42.21`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/barrier` | Состояние барьера и всех датчиков |
| GET | `/api/barrier/{sensor}` | Один датчик: `top`, `middle`, `bottom` |
| POST, PUT, PATCH | `/api/barrier/reset` | Обнулить счётчики |
| GET | `/api/config` | Пороги и гистерезис |
| PUT, PATCH, POST | `/api/config` | `{"all":60,"bottom":40}` — пороги в см, целые 1–500; порог датчика важнее `all`; сохраняются в EEPROM |

### Как считаются данные

- Каждый датчик опрашивается раз в 10 мс, расстояние считается по медиане последних 5 замеров: одиночные выбросы не дают ложных срабатываний.
- Расстояние, см = 65 × U^−1,10, где U — напряжение с датчика. Больше 500 см или нулевое напряжение — «вне диапазона», в JSON `"distance_cm": null`.
- Датчик перекрыт, когда расстояние меньше порога, и освобождается, когда оно больше порога + 5 см (гистерезис). Датчик вне диапазона считается свободным.
- Счётчики `count` растут в момент перекрытия: у каждого датчика свой, у барьера общий. Человек, перекрывший два датчика сразу, даёт барьеру +1. Чтобы не пропустить быстрый проход между опросами, следите за `count`, а не только за `blocked`. Счётчики обнуляются при перезагрузке.
- Аналоговые ИК-датчики вплотную (ближе своего минимума, обычно 10–20 см) дают то же напряжение, что и на дальнем расстоянии: предмет у самого датчика может читаться как далёкий.

Ответ `GET /api/barrier` (отформатирован для чтения):

```json
{
  "status": "ok",
  "blocked": true,
  "count": 7,
  "sensors": {
    "top":    {"distance_cm": 118,  "volts": 0.58, "threshold_cm": 50, "blocked": false, "count": 2},
    "middle": {"distance_cm": 34,   "volts": 1.85, "threshold_cm": 50, "blocked": true,  "count": 5},
    "bottom": {"distance_cm": null, "volts": 0.00, "threshold_cm": 40, "blocked": false, "count": 0}
  }
}
```

`GET /api/barrier/middle` возвращает те же поля для одного датчика с полем `"sensor":"middle"`. `GET /api/config` возвращает `{"status":"ok","threshold_cm":{"top":50,"middle":50,"bottom":50},"hysteresis_cm":5}`.

**Как подобрать порог:** посмотрите `distance_cm` при свободном проходе и поставьте порог на 15–20 см меньше. Если датчики видят фон на разном расстоянии, задайте пороги по отдельности.

```bash
curl -X PATCH http://192.168.42.21/api/config \
  -H "Content-Type: application/json" \
  -d '{"all":60,"bottom":40}'
```

## Ошибки

Все ошибки приходят в формате `{"status":"error","error":"текст"}`; при ошибке устройство ничего не меняет.

| Код | Текст `error` | Когда | Устройства |
| --- | --- | --- | --- |
| 400 | `bad request line` | Некорректная строка запроса | Все |
| 400 | `bad content length` | `Content-Length` не число | Терминал, барьер |
| 400 | `invalid JSON` | Тело не плоский JSON-объект | Терминал, барьер |
| 400 | `led value must be true or false` | Значение светодиода не `true`/`false`/`1`/`0` | Лампа, терминал |
| 400 | `expected JSON with red, blue, green or yellow` | В `/api/lamp` (`/api/leds`) нет ни одного цвета | Лампа, терминал |
| 400 | `expected JSON with on: true or false` | В `/api/lamp/{color}` нет поля `on` | Лампа, терминал |
| 400 | `expected JSON with line0, line1, line2 or line3` | В `/api/display` нет ни одной строки | Терминал |
| 400 | `expected JSON with text` | В `/api/display/{line}` нет поля `text` | Терминал |
| 400 | `text must be a string` | Текст не строка | Терминал |
| 400 | `text longer than 20 characters` | Строка длиннее 20 символов | Терминал |
| 400 | `unsupported character` | Символ, который дисплей не покажет (эмодзи, украинские буквы, `\`, `~`, перевод строки) | Терминал |
| 400 | `invalid UTF-8` | Текст не в UTF-8 | Терминал |
| 400 | `too many different Cyrillic letters on screen (max 8)` | На экране оказалось бы больше 8 разных своих русских букв | Терминал |
| 400 | `threshold must be an integer 1-500` | Порог не целое число от 1 до 500 | Барьер |
| 400 | `expected JSON with top, middle, bottom or all` | В `/api/config` нет ни одного порога | Барьер |
| 404 | `not found` | Неизвестный путь или действие | Все |
| 404 | `unknown color` | Неизвестный цвет | Лампа, терминал |
| 404 | `unknown line` | Номер строки не от 0 до 3 | Терминал |
| 404 | `unknown sensor` | Неизвестный датчик | Барьер |
| 405 | `method not allowed` | Метод не подходит к пути (`GET` на `/toggle`, `DELETE`) | Все |
| 408 | `request timeout` | Запрос не пришёл целиком за 1,5 с | Все |
| 413 | `body too large` | Тело больше лимита: лампа 95, терминал 600, барьер 127 байт | Все |

## Настройка по Serial

Все устройства настраиваются по USB-кабелю на скорости 115200 бод. В конце команды нужен перевод строки: в мониторе порта Arduino IDE выберите «Новая строка» или «NL & CR».

| Команда | Действие | Устройства |
| --- | --- | --- |
| `help` | Список команд | Все |
| `ip` | Показать текущий IP (терминал и барьер ещё и MAC) | Все |
| `ip 192.168.2.30` | Задать новый IP: сохраняется в EEPROM и применяется сразу | Все |
| `ip default` | Вернуть адрес по умолчанию | Все |
| `1010` | Светодиоды красный, синий, зелёный, жёлтый (`0`/`1` по порядку) | Лампа, терминал |
| `status` | Всё состояние устройства | Терминал, барьер |
| `reset` | Обнулить счётчики | Терминал, барьер |
| `text 0 Привет` | Записать текст в строку дисплея 0–3 | Терминал |
| `clear` | Очистить дисплей | Терминал |
| `threshold` | Показать пороги | Барьер |
| `threshold 40` | Порог для всех датчиков, см | Барьер |
| `threshold top 40` | Порог для одного датчика (`top`, `middle`, `bottom`) | Барьер |
| `watch` | Вкл./выкл. вывод расстояний раз в секунду | Барьер |

Правила для IP у всех устройств одинаковые: четыре числа 0–255; отклоняются `127.x.x.x`, адреса от 224 и выше, нулевой первый октет и адреса на `.0` или `.255`. Маска всегда 255.255.255.0, поэтому компьютер должен быть в той же подсети /24. MAC строится из IP и меняется вместе с ним: у терминала `02:52:` + четыре октета IP, у барьера `02:49:` + четыре октета IP.

При нажатии кнопок терминал пишет в Serial строку вида `green button press (start)`, а барьер при перекрытии — `middle blocked, 34 cm` и `middle clear`.

## Пример клиента на Python

Сервер опрашивает барьер и терминал раз в 200 мс: при проходе мигает лампой и пишет счётчик на дисплей, при kill switch зажигает красный.

```python
import time
import requests

LAMP = "http://192.168.2.21"
TERM = "http://192.168.2.22"
BARRIER = "http://192.168.42.21"

requests.patch(f"{BARRIER}/api/config", json={"all": 60})
requests.post(f"{BARRIER}/api/barrier/reset")
requests.post(f"{TERM}/api/buttons/reset")
requests.patch(f"{TERM}/api/display", json={"line0": "Готов", "line1": "Проходов: 0"})

passes = 0
last_buttons = requests.get(f"{TERM}/api/buttons").json()["buttons"]

while True:
    barrier = requests.get(f"{BARRIER}/api/barrier").json()
    term = requests.get(f"{TERM}/api/terminal").json()

    if barrier["count"] != passes:
        passes = barrier["count"]
        requests.post(f"{LAMP}/api/lamp/green/toggle")
        r = requests.put(f"{TERM}/api/display/1", json={"text": f"Проходов: {passes}"})
        if r.status_code == 400:
            print(r.json()["error"])   # например, больше 8 разных русских букв

    if term["kill_switch"]:
        requests.patch(f"{LAMP}/api/lamp", json={"red": True})

    for name, btn in term["buttons"].items():
        if btn["count"] != last_buttons[name]["count"]:
            print(f"Нажата кнопка {name}")
    last_buttons = term["buttons"]

    time.sleep(0.2)
```
